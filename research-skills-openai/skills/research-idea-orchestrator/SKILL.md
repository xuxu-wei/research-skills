# Research Idea Development

Turn the user's starting point into research options that are scientifically meaningful and feasible. Own the planning, drafting, revision, and final comparison.

## Writing and editing

Use [$academic-writer](../academic-writer/SKILL.md) to draft researcher-facing prose and [$academic-humanizer](../academic-humanizer/SKILL.md) to edit each complete draft before scientific review or delivery. The authoring task performs both steps; retain independent reviewers' findings and dissent unchanged. Changes to scientific meaning follow the substantive-revision requirements below.

## Approach

1. Establish the scientific question, intended contribution, available evidence or data, and practical constraints. Use what the user has provided; ask only for missing information that materially affects the direction.
2. Examine the evidence needed to distinguish an open question from an unsupported novelty claim. Use available search or database tools when useful. Keep source pointers and separate documented findings from assumptions; incomplete access should narrow confidence, not invite invented evidence.
3. Develop as many distinct options as the decision warrants. Explain the question, why it matters, what work would answer it, the expected contribution, and the main uncertainty for each. Replication, validation, negative results, and useful resources can be worthwhile contributions.
4. Check that the proposed methods can answer the question with accessible data and realistic resources. For difficult framing choices, consult [research design considerations](references/research-design.md).
5. Have a fresh instance use [$research-evaluator](../research-evaluator/SKILL.md) to review the current ideas with the relevant source material and user constraints, including any unresolved design or feasibility questions. Do not supply an expected verdict or the drafter's private reasoning.
6. Revise in response to supported findings. Preserve reasoned disagreements. Substantial changes to the question, methods, evidence, or claims need a new version and fresh independent review; wording changes do not.
7. Present the options, their tradeoffs, the review findings, and a recommendation with its rationale. The user chooses which direction to pursue.

## Delivery

Use a readable comparison or individual idea notes, with sufficient sources and method detail to support the decision. Identify the reviewed version and unresolved issues without requiring a separate registry or prescribed file layout.

If independent review is unavailable, deliver the useful draft and state that it has not been independently reviewed. Stop revising when further progress depends on evidence, access, resources, or a research choice that the user must provide. Explain what would resolve the remaining uncertainty.
