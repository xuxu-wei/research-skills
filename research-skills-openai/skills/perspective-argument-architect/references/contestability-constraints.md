# Contestability Constraints

替代僵硬的"每一步必须可证伪"。Perspective 中的主张不仅包括经验命题，也包括概念重构、价值判断、政策优先、转化路径和框架性解释。使用五类约束确保每一步论证都有可检验的边界。

## Five Constraint Types

论证链每一步**至少选择一种**约束。多选鼓励。

### 1. Falsifiable Condition（可证伪条件）

什么证据会推翻该主张？

适用：经验性、机制性、因果推断类主张。

```
示例主张："方案 X 在条件 Y 下改善了预先定义的结果 Z"
可证伪条件：如果独立、适配条件 Y 的直接检验显示结果 Z 未改善，则该主张不成立。
```

### 2. Debatable Point（可争议点）

一个强反方会如何质疑该主张？

适用：概念性、框架性、解释性主张。

```
示例主张："使用情境的系统约束是决定工具效用的主要因素"
可争议点：反对者可能主张工具的内在性能才是主要因素，情境约束只影响次要结果。
```

### 3. Boundary Condition（边界条件）

在哪些情境下该主张不成立？

适用：所有类型。

```
示例主张："定向部署通常优于普遍部署"
边界条件：当对象高度同质、部署成本可忽略且漏覆盖代价很高时，普遍部署可能更优。
```

### 4. Alternative Explanation（替代解释）

是否存在更简单、更保守的解释？

适用：因果推断、机制性、解释性主张。

```
示例主张："多组成部分方案的效果来自各部分之间的协同"
替代解释：观察到的效果可能主要由一个组成部分解释，其余部分并未产生独立贡献。
```

### 5. Implementation Limit（实施限制）

如果是实践或政策建议，现实约束是什么？

适用：转化性、政策建议、实践指导类主张。

```
示例主张："应将工具 X 纳入常规工作流程"
实施限制：需要解决基础设施、培训、责任归属、维护和持续更新问题。
```

## Usage

论证链每一步的模板：

```markdown
### Step N: [主张]

Contestability constraint (至少一种):
  - Falsifiable condition: [...]
  - Debatable point: [...]
  - Boundary condition: [...]
  - Alternative explanation: [...]
  - Implementation limit: [...]
```

## Anti-Patterns

- **空约束**：写"可证伪条件：如果有证据反对"——这不是真正的约束
- **strawman 可争议点**：使用弱版本的反对意见
- **边界过于宽泛**："在所有场景中均适用"——等于没有边界
- **完全跳过**：某步没有任何约束——这是伪论证
