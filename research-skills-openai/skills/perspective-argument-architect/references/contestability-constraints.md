# Contestability Constraints

替代僵硬的"每一步必须可证伪"。Perspective 中的主张不仅包括经验命题，也包括概念重构、价值判断、政策优先、转化路径和框架性解释。使用五类约束确保每一步论证都有可检验的边界。

## Five Constraint Types

论证链每一步**至少选择一种**约束。多选鼓励。

### 1. Falsifiable Condition（可证伪条件）

什么证据会推翻该主张？

适用：经验性、机制性、因果推断类主张。

```
示例主张："AI 辅助诊断系统将临床误诊率降低了 30%"
可证伪条件：如果一项多中心 RCT 显示 AI 辅助组与对照组误诊率无显著差异，则该主张被推翻。
```

### 2. Debatable Point（可争议点）

一个强反方会如何质疑该主张？

适用：概念性、框架性、解释性主张。

```
示例主张："临床工作流的系统约束是决定 AI 效用的主要因素"
可争议点：反对者可能主张 AI 准确率本身是主要因素——在模型性能达到阈值之前，工作流是次要的。
```

### 3. Boundary Condition（边界条件）

在哪些情境下该主张不成立？

适用：所有类型。

```
示例主张："早期筛查应优先考虑风险分层而非普遍覆盖"
边界条件：当疾病负担极重且筛查成本极低时（如某些传染病），普遍覆盖可能更优。
```

### 4. Alternative Explanation（替代解释）

是否存在更简单、更保守的解释？

适用：因果推断、机制性、解释性主张。

```
示例主张："中药复方通过多靶点协同作用产生疗效"
替代解释：可能只有一个主要活性成分起作用，其他成分的药代动力学贡献可以忽略。
```

### 5. Implementation Limit（实施限制）

如果是实践或政策建议，现实约束是什么？

适用：转化性、政策建议、实践指导类主张。

```
示例主张："应将 AI 辅助诊断纳入基层医疗常规"
实施限制：需要解决基层网络基础设施、培训成本、责任归属和持续模型更新机制。
```

## Usage

论证链每一步的模板：

```markdown
### Step N: [主张]

Contestability constraint (至少一种):
  - Falsifiable condition: [...]
  - Debatable point: [...]
  - Boundary condition: [...]
  - Alternative explanation: [...]
  - Implementation limit: [...]
```

## Anti-Patterns

- **空约束**：写"可证伪条件：如果有证据反对"——这不是真正的约束
- **strawman 可争议点**：使用弱版本的反对意见
- **边界过于宽泛**："在所有医疗场景中均适用"——等于没有边界
- **完全跳过**：某步没有任何约束——这是伪论证
