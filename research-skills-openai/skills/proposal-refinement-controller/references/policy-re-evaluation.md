# Re-evaluation Policy

## Purpose

Ensure each revision is assessed by an isolated, independent evaluator.

## Required Inputs

- Updated proposal file path.
- Previous proposal file path or version.
- An anonymized prior must-fix issue list with no scores, overall rationale, or decision.
- Revision delta report.
- Context brief.
- User goals and constraints.

## Isolation Requirements

The re-evaluator must not be the drafter, refiner, or a self-checking continuation of the drafting context.

The re-evaluator should only see the frozen proposal versions, anonymized must-fix issue list, revision delta, and necessary factual context. It must not see hidden drafting rationale, prior scores, overall rationale, or the prior decision.

## Required Comparison

The re-evaluation must answer:

- Were the previous must-fix issues resolved?
- Were new defects introduced?
- Did the revision change the research question, aims, methods, or claims?
- Was the improvement substantive or merely stylistic?
- Should the proposal accept, revise again, reject, or stop for no gain?
