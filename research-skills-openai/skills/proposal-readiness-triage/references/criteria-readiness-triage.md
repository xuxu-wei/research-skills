# Readiness Triage Criteria

Use this file to determine whether a research idea is ready for proposal drafting.

## Rating Labels

Use three labels for each criterion:

- `pass`: sufficient for drafting.
- `concern`: incomplete but not necessarily blocking.
- `fail`: blocks responsible drafting unless clarified or redesigned.

## Core Criteria

### 1. Research Domain

The domain or problem area should be identifiable enough to orient reviewers and literature framing.

- pass: field and problem area are clear.
- concern: broad field is clear, but subdomain is vague.
- fail: no usable research domain.

### 2. Research Question or Objective

The idea should contain an answerable question, objective, or aim.

- pass: question or objective is answerable.
- concern: direction is clear but needs narrowing.
- fail: only a topic, interest, or slogan is present.

### 3. Study Object

The population, dataset, system, corpus, intervention, material, phenomenon, or target object should be identifiable.

- pass: study object is explicit.
- concern: object is implied but underspecified.
- fail: no study object.

### 4. Value Claim

The idea should state why the work matters.

- pass: scientific, clinical, engineering, policy, educational, or methodological value is clear.
- concern: value is plausible but generic.
- fail: no clear value beyond interest.

### 5. Intended Output

The desired output should be known or inferable.

Examples: paper, grant, protocol, pilot study, method paper, benchmark, review, dataset, implementation plan.

- pass: target output is explicit or strongly implied.
- concern: output is ambiguous but recoverable.
- fail: output type is unknown and affects design.

### 6. Data or Evidence Path

The proposal should have a plausible path to data, evidence, experiment, corpus, benchmark, or implementation material.

- pass: available or obtainable evidence path is clear.
- concern: evidence path is plausible but not specific.
- fail: no credible data or evidence path.

### 7. Endpoint, Outcome, Metric, or Deliverable

There should be a way to judge success or answer the question.

- pass: endpoint, outcome, metric, or deliverable is identifiable.
- concern: evaluation target is implied but needs refinement.
- fail: no evaluable target.

### 8. Method or Study Design

A plausible methodological route should exist.

- pass: method or design is clear enough for drafting.
- concern: method category is plausible but underspecified.
- fail: no method route or clear mismatch.

### 9. Feasibility Constraints

Known time, resource, access, method, or collaboration constraints should not obviously block the work.

- pass: constraints appear manageable.
- concern: constraints need checking.
- fail: known constraint blocks execution.

### 10. User Goal Fit

The idea should fit the user's stated goal.

- pass: aligned with user goal and output type.
- concern: partially aligned or unclear.
- fail: mismatch with user goal.

## Minimum Passing Pattern

`ready_for_proposal` generally requires:

- no fatal flaw;
- no fail on research question / objective;
- no fail on study object;
- no fail on data or evidence path;
- no fail on endpoint / outcome / metric / deliverable;
- no fail on user goal fit;
- method route at least concern, preferably pass.

A criterion may be marked `concern` if the missing detail can be responsibly handled during drafting without fabricating key facts.
