# Proposal Genre Awareness

Proposal 是说服性文档（persuasive），不是教学材料（pedagogical）、文献综述（review）或博客（blog）。所有写作决策必须遵守体裁边界。

## 核心原则

- **以目标读者为准。** 不把所有评审都假定为同一层级的领域专家。依据 `target_reader_profile` 与 `reader_prior_knowledge` 决定哪些概念可直接使用、哪些术语需要在首次承担推理功能前定义。
- **清晰来自功能与顺序。** 解释应帮助读者完成问题、知识、缺口、意义与方案理由之间的推理；不服务这条链的说明应删除或重写。
- **每个段落承担可识别功能。** 当一个段落混合多个推理任务而妨碍 reader handoff 时拆分；当多个段落重复同一功能而不增加证据或必要边界时合并。

## 需要功能论证的体裁特征

### 1. 教学式修辞问句

```
✗ "为什么现在？近期变化暴露了现有方案在关键条件下的不稳定性……"
✗ "为什么采用这一路径？上述场景展示了一个特殊结构……"
✓ 直接陈述："近期变化暴露了现有方案在关键条件下的不稳定性，形成了需要解决的明确缺口。"
✓ 直接陈述："所选路径能够处理该结构，因为它支持研究对象的关键约束。"
```

修辞问句不是自动缺陷。若它增加解码负担、替代 significance 论证或破坏 reader handoff，应改为直接陈述；精确研究问题或绑定栏目要求的问句可以保留。

### 2. 人物化应用场景

```
✗ "一位一线使用者在日常工作中遇到困难，于是查找资料、咨询同事，最后仍无法作出决定……"
✓ "在目标场景中，现有流程无法在关键约束下产生决策所需输出，导致可验证的执行偏差。"
```

应用场景可以提供 motivation，但人物叙事只有在它承载不可替代的决策信息且目标体裁允许时才值得保留。通常应直接描述对象、约束与可验证后果，减少与判断无关的故事负担。

### 3. 术语词典化翻译表

```
✗ 在正文开头嵌入覆盖两个领域全部概念的长篇对照表
✓ 简短说明："附录术语表仅映射后文反复承担推理功能的跨领域术语。"
```

只有当绑定格式允许且跨学科术语确实构成持续负担时才使用附录对照表。正文仍应在读者首次需要某术语时提供完成当前推理所需的最小定义。

### 4. "阅读指南"框架

```
✗ "阅读指南：本提案涉及领域 A 与领域 B 的术语交叉，建议先浏览术语表再返回正文。"
✓ 通常不需要这种元注释。直接开始写内容；如果交叉领域确实需要前置说明，在读者首次需要时用最小充分说明解决。
```

## 修订时的功能规则

**每条 reviewer 建议的默认处理模式是"替换或浓缩"，不是"追加"。**

```
错误模式：建议"缺少应用动机" → 追加多个关于人物经历的叙事段落
正确模式：建议"缺少应用动机" → 在意义论证中嵌入完成判断所需的对象、约束与后果
```

如果必须新增内容，先说明新增内容承担的修复功能、替代或重组哪些现有材料，以及它如何改善 reader handoff。篇幅变化由绑定上限和论证功能决定，不使用统一句数、段数或增长比例。

## 评审视角

读者可能按标题、摘要、意义、方法、可行性和证据进行非线性浏览。内容计划应让关键判断在这种浏览方式下仍可定位，同时保持顺序阅读时的完整 reasoning chain。

在这条路径上，术语表、应用场景或 QA 段落只有在显著降低目标读者的理解成本、保持非线性定位并推进 reasoning chain 时才有价值。若它们只占用空间或造成回读，应删除或改为直接论证；不得仅凭句式类别判定缺陷。
