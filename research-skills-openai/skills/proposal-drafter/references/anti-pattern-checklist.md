# Proposal Anti-Pattern Checklist

proposal-drafter 完成手稿后、handoff 前逐条自检。出现以下问题时，判断其严重程度并选择处理策略。

## 一、核心主张

- [ ] 核心主张能否被清楚、稳定地识别，并与研究问题和设计相互回指？
  - 若不能：检查限定、并列目标或术语负担是否遮蔽了主张；将真正的工作假设和风险放入权威的 `Assumptions, feasibility, and risks` 位置。

- [ ] 限定条件是否帮助读者理解适用范围，还是遮蔽了可检验主张？
  - 将研究要回答的问题与执行所依赖的条件分开；条件性方法假设只在权威位置记录一次。

- [ ] 是否存在"若A则X，若A不成立则Y——两者均构成实质进步"的对称构造？
  - 若存在：考虑这种对称是否削弱了主张的方向性。如果A是研究要验证的核心假设，不需要用"如果假设不成立也有贡献"来降低风险感知——把真正的科学意义放入意义论证，把执行风险放入权威的 `Assumptions, feasibility, and risks` 位置，不嵌入主张本身。

## 二、正文语言

- [ ] 正文是否包含任何指向外部评审意见的表述（"根据审稿人""为回应质疑""对此补充"等）？
  - 若包含：这些表述的实质修改是否可以直接融入正文而不需要注明来源？如果可以，删掉来源标注，只保留修改。如果不能（即修改本身依赖"审稿人提出"才能成立），迁移至独立的审稿回应文件。

- [ ] 正文是否包含对自身修改的评价性元语言（"修改后更清晰""新版本改进了"等）？
  - 若包含：删除。正文的目的是陈述研究计划，不是评价写作过程。

- [ ] 正文中是否有独立的"前置声明"或"贡献定位说明"段落？
  - 若有：这类段落通常不应该在 proposal 中出现。应判断其功能——是向读者解释研究贡献的边界，可以保留但应精简；是回应某个已经不在正文中的质疑，应删除或迁移至审稿回应文件。

## 三、篇幅与结构

- [ ] 是否有单独存在的"为什么是现在"叙事段？
  - 若有：考虑这段的紧迫性论证是否可以通过 gap 分析本身传递。如果可以，拆散融入，不设独立段。

- [ ] 是否有教学式的概念解释段？
  - 若有：判断目标读者是否需要这段解释，以及它是否在首次依赖该概念前推进 reader reasoning chain。使用完成该功能所需的最小充分形式；当一个段落确有必要时可以保留，不按段落形式本身判定缺陷。

- [ ] 是否有叙事化的临床场景或修辞问句？
  - 若有：判断它们是否以不可替代的方式推进 gap、意义、设计理由或绑定栏目功能。若直接陈述能以更低负担完成同一功能，应改写；精确研究问题或目标体裁确有要求时可保留。

- [ ] 本轮新增内容是否承担明确的修复功能，并替代、重组或补足了相应缺口？
  - 若新增内容只叠加说明或 caveat 而没有改善 reasoning chain，应改为替换、合并或删减。

## 四、语言风格

- [ ] 核心动词是承诺性的（提出、构建、验证、比较、估计）还是尝试性的（探索、尝试、讨论、思考）？
  - 若以尝试性动词为主：考虑这些不确定性中，哪些是研究设计本身的不确定性（应由权威的 `Assumptions, feasibility, and risks` 位置承载），哪些是表述习惯。前者只在该权威位置记录，后者替换为与实际承诺相称的表述。

- [ ] 全文读起来是"我要做什么"还是"我已经回应了哪些质疑"？
  - 若偏后者：审稿回应文件和 proposal 正文的边界可能模糊了。检查是否所有回应性内容都已迁出正文。
