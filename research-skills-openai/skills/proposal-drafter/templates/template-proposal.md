# template-proposal

> 使用规则：若用户显式指定 proposal 结构、funding call 模板、机构模板或其他格式要求，应优先按用户要求撰写。若用户未指定结构，使用本推荐结构。

# Proposal Title

填写项目标题或工作标题。若标题尚未确定，标记为 working title。

# 1. 项目的立项依据

## 1.1 选题价值

用一句话定位研究问题的大背景，随即提出证据能够支持的高价值现实或科学问题、其广泛性或重要性，以及本项目要突破的核心制约。纯理论项目应使用真实的科学或方法学瓶颈，不虚构现实应用；“最紧迫”“最核心”等表述必须与证据强度一致。

应结合以下至少一种角度论述：

- 科学研究发展趋势及科学意义；
- 国民经济和社会发展中迫切需要解决的关键科技问题及应用前景；
- 临床、工程、公共卫生、社会或方法学中的重要未满足需求。

如证据不足，应标记待补充文献或待核查证据。

## 1.2 国内外研究现状

按正式内容计划选定的路径组织：系统式写法逐项分析问题组件或制约，每个单元都落到本项目组件，合起来覆盖研究内容；递进式写法使小标题、首句和末句形成连续逻辑链，递进过程映射研究路径并最终聚焦本项目。不得把文献罗列冒充 gap 论证。

综上，用一段话收束已建立的 gap、本项目概述、路线或方法、创新定位与意义；不重复后文方法细节，也不引入新证据。绑定模板可用功能等价的标题和连接方式。

## 参考文献

列出主要参考文献目录。

若没有可核查文献，不得编造；应写明“需补充主要参考文献”。

# 2. 项目的研究内容、研究目标，以及拟解决的关键科学问题

此部分为重点阐述内容。

应包括：

- 研究内容；
- 总体研究目标；
- 具体目标或 aims；
- 拟解决的关键科学问题；
- 核心假设，如适用；
- 研究对象、系统、数据或人群。

# 3. 拟采取的研究方案及可行性分析

说明研究方法、技术路线、实验手段、关键技术等。

## 3.1 拟采取的研究方案

应包括：

- 研究设计；
- 技术路线；
- 数据来源或实验材料；
- 关键方法；
- 主要分析或验证路径；
- 使设计能够回答研究问题所需的操作细节。

## 3.2 Assumptions, feasibility, and risks（假设、可行性与风险）

这是全文关于假设、可行性与风险的唯一权威位置。应包括：

- 已接受的工作假设，包括仅在特定条件成立时适用的方法假设；每项只记录一次；
- 数据或实验条件可行性；
- 方法和技术可行性；
- 时间和资源可行性；
- 数据访问、技术或协作约束；
- 主要风险、触发条件与应对策略。

其他章节不重复列出限制。仅当某项边界直接推进当前位置的论证、且省略会歪曲相邻设计选择时，才在该处直接说明该边界；不要使用“见本节”等跳转提示。

# 4. 本项目的特色与创新之处

说明本项目相对于既有研究或实践方案的特色与潜在创新。

可包括：

- 理论创新；
- 方法创新；
- 数据或资源创新；
- 评价指标或 benchmark 创新；
- 应用场景或转化价值；
- 跨学科整合。

不得夸大 novelty；证据不足时应写为潜在创新点。

# 5. 研究时间计划及预期研究成果

应包括：

- 阶段性时间计划；
- 每阶段主要任务；
- 预期研究成果；
- 可交付产物；
- 论文、基金、protocol、软件、数据资源、模型或报告等目标产出，如适用。
