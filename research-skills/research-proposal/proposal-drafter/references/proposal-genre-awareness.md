# Proposal Genre Awareness

Proposal 是说服性文档（persuasive），不是教学材料（pedagogical）、文献综述（review）或博客（blog）。所有写作决策必须遵守体裁边界。

## 核心原则

- **评审专家是领域同行，不需要被"教"。** 他们知道随机效应模型是什么，知道GRADE是什么，知道发表偏倚是什么。你的任务是说服他们你的研究值得资助，不是帮助他们理解你的研究。
- **清晰 ≠ 解释过度。** 一个清晰的观点用一句话就够了。如果一段话在"帮读者理解"而不是"支撑论点"，它应该被删掉。
- **每个段落必须服务于核心论点。** 问自己：如果删掉这一段，核心论证会受损吗？如果不会，删掉它。

## 禁止的体裁特征

### 1. 教学式修辞问句

```
✗ "为什么现在？COVID-19大流行暴露了快速证据合成中小k推断的脆弱性..."
✗ "为什么是系统辨识？上述临床场景展示了一个数学结构..."
✓ 直接陈述："COVID-19大流行暴露了快速证据合成中小k推断的脆弱性，这创造了一个紧迫的方法学需求。"
✓ 直接陈述："系统辨识天然处理这种场景——它原生支持非持续激励和饱和观测。"
```

修辞问句是 blog/expository 的标志。在 proposal 中，读者已知问题的重要性——他们读 proposal 是为了判断你是否能解决它。

### 2. 叙事化临床场景

```
✗ "一位心内科医生在查房时遇到一个问题——对于急性心肌梗死后射血分数降低的患者
   ，早期使用β受体阻滞剂是否降低全因死亡率？她找到一篇最新的Cochrane综述..."
✓ "例如，一项仅纳入7项RCT的Cochrane综述（k=7, n=2,800）显示HR=0.78 (95%CI 0.61-0.99)。
   当前框架下，临床解读只能是'证据质量中等'——因为GRADE因不精确性降级。"
```

临床场景作为motivation是有效的——但用人物叙事来展示motivation是blog的语言。直接描述场景的数学特征，而不是编故事。

### 3. 术语词典化翻译表

```
✗ 13行"控制理论↔Meta分析"对照表嵌入1.2节开头
✓ 一句话："表1（附录）给出了控制理论与Meta分析的关键术语映射。"
```

评审专家会翻到附录看术语对照如果他们需要。把对照表放在正文前面意味着你觉得读者看不懂你的术语——这是一种自我削弱的修辞动作。

### 4. "阅读指南"框架

```
✗ "阅读指南：概念翻译表——以下提案涉及控制理论与Meta分析两个领域的术语交叉
   ，建议在阅读1.2.2系统辨识部分之前先浏览本表。"
✓ 不需要这种元注释。直接开始写内容。如果交叉领域确实需要前置说明，用一句话在摘要或引言末尾解决。
```

## 修订时的减法规则

**每条 reviewer 建议的默认处理模式是"替换或浓缩"，不是"追加"。**

```
错误模式：MF-1 建议"缺临床场景" → 新增3段临床叙事 ✓
正确模式：MF-1 建议"缺临床场景" → 在1.1研究意义中嵌入一句临床锚点（浓缩在现有段落中）
```

如果必须新增内容：
1. 新段不能超过 5 句
2. 与之相邻的旧段必须至少浓缩 1/3
3. 修订后 proposal 总字符数增加不超过 10%

## 评审视角

一位国自然评审专家的典型阅读路径：
1. 看标题 → 判断方向
2. 看摘要 → 判断水准
3. 翻研究方法 → 确认可行性
4. 扫参考文献 → 确认文献功底
5. 做决定

在这条路径上，"解释性辅助材料"（术语表、临床场景故事、QA段落）不被需要也不会被阅读。它们占用空间但不提供信息价值。一个干净、干练、直接论证的 proposal 比一个充满帮助性解释的 proposal 更有说服力。
