# Proposal Anti-Pattern Checklist

proposal-drafter 完成手稿后、handoff 前逐条自检。出现以下问题时，判断其严重程度并选择处理策略。

## 一、核心主张

- [ ] 核心主张能否在一句话内完整表述，不含嵌套条件限定？
  - 若不能：主张可能已被过多限定稀释。考虑：删减最弱的一层限定，或将其移入"风险与局限性"。

- [ ] 核心主张的限定条件是否超过 2 层？
  - 若超过：每一层限定都在收窄主张的适用范围。考虑：其中某一层是否应是研究本身要回答的问题而非承诺的前提？若是，将其从"前提"改为"待验证假设"。

- [ ] 是否存在"若A则X，若A不成立则Y——两者均构成实质进步"的对称构造？
  - 若存在：考虑这种对称是否削弱了主张的方向性。如果A是研究要验证的核心假设，不需要用"如果假设不成立也有贡献"来降低风险感知——把"假设不成立时的价值"放回研究意义或风险控制中陈述，不嵌入主张本身。

## 二、正文语言

- [ ] 正文是否包含任何指向外部评审意见的表述（"根据审稿人""为回应质疑""对此补充"等）？
  - 若包含：这些表述的实质修改是否可以直接融入正文而不需要注明来源？如果可以，删掉来源标注，只保留修改。如果不能（即修改本身依赖"审稿人提出"才能成立），迁移至独立的审稿回应文件。

- [ ] 正文是否包含对自身修改的评价性元语言（"修改后更清晰""新版本改进了"等）？
  - 若包含：删除。正文的目的是陈述研究计划，不是评价写作过程。

- [ ] 正文中是否有独立的"前置声明"或"贡献定位说明"段落？
  - 若有：这类段落通常不应该在 proposal 中出现。应判断其功能——是向读者解释研究贡献的边界，可以保留但应精简；是回应某个已经不在正文中的质疑，应删除或迁移至审稿回应文件。

## 三、篇幅与结构

- [ ] 是否有单独存在的"为什么是现在"叙事段？
  - 若有：考虑这段的紧迫性论证是否可以通过 gap 分析本身传递。如果可以，拆散融入，不设独立段。

- [ ] 是否有教学式的概念解释段？
  - 若有：判断目标读者是否需要这段解释。基金评审通常不需要教科书。如果确实必要，允许术语的简明解释，不用段落。

- [ ] 是否有叙事化的临床场景或修辞问句？
  - 若有：判断它们是为论点服务还是为可读性服务。若为论点服务——改为直接陈述。若为可读性——proposal 不是科普文章，可读性应通过结构清晰度和语言精炼来达成。

- [ ] 本轮修订新增的段落是否超过修订前总段数的 15%？
  - 若超过：本轮修订以追加为主。回顾 revision plan——是否有可通过替换或删减处理的条目被以追加方式执行了？

## 四、语言风格

- [ ] 核心动词是承诺性的（提出、构建、验证、比较、估计）还是尝试性的（探索、尝试、讨论、思考）？
  - 若以尝试性动词为主：考虑这些不确定性中，哪些是研究设计本身的不确定性（应由风险控制章节承载），哪些是表述习惯。前者保留在风险控制中，后者替换为承诺性表述。

- [ ] 全文读起来是"我要做什么"还是"我已经回应了哪些质疑"？
  - 若偏后者：审稿回应文件和 proposal 正文的边界可能模糊了。检查是否所有回应性内容都已迁出正文。
